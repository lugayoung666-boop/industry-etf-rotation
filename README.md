# 基于“变盘指数”的行业主题ETF动量—反转轮动策略

## 1. 项目简介

本项目是一个基金/ETF轮动策略的小型金工项目。第一阶段参考“变盘指数”动量择时及行业轮动方法，构建可以完整运行的最小可行版本（MVP）。

MVP的核心思路是：先构造“变盘指数”，判断当前行业结构更适合使用动量信号还是反转信号；再对行业进行横截面排序和轮动配置；最后将入选行业映射到对应的基金/ETF并完成回测。

本项目不是纯动量或纯反转策略。动量和反转均为策略组成部分，“变盘指数”负责决定每个调仓期采用哪一种信号。当前工作重点是跑通数据、信号、组合、交易和绩效统计链路，不预设策略一定取得正收益。

> **当前仓库状态：** 下文记录的是待接入程序的运行方式、目标结构和核验标准。

## 2. 研究对象与数据架构

第一阶段以行业或主题ETF为主要交易载体，行业或主题示例包括医药、消费、科技、红利、军工和新能源。这些仅为方向示例，不代表候选池固定为6只ETF。为了支持横截面排名和五组分层，MVP应尽可能使用覆盖较完整的行业池。

计划采用以下两层结构：

- **信号层：** 优先使用覆盖时间较长、分类稳定的行业指数，计算变盘指数、动量因子和反转因子；
- **交易层：** 将入选行业映射到对应的代表性行业或主题ETF，使用ETF价格模拟实际交易；
- **简化MVP：** 暂时无法取得完整行业指数数据，先使用历史覆盖足够长的ETF池验证程序流程简化实现；
- **映射约束：** ETF映射需要考虑跟踪指数、上市日期、流动性和重复暴露。

本项目不开展个股层面的选股研究。场外基金作为后续扩展方向，第一版不混用ETF价格与场外基金净值进行回测。

## 3. 基准策略逻辑

### 3.1 变盘指数

设有效行业数量为 $N$。在每个交易日 $t$，根据各行业滚动月度收益率进行横截面排名，并比较行业 $i$ 在当前时点与 $M$ 个交易日前的排名变化。

标准化排名变化为：

$$
\mathrm{RankStd}_{i,t}=\left|\frac{\Delta \mathrm{Rank}_{i,t}}{N}\right|
$$

全部行业标准化排名变化的横截面均值为：

$$
R_t=\frac{1}{N}\sum_{i=1}^{N}\mathrm{RankStd}_{i,t}
$$

对 $R_t$ 计算过去 $M$ 个交易日的滚动标准差：

$$
I_t = \mathrm{Std}_M(R_t)
$$

再对 $I_t$ 进行 $m$ 日移动平均，得到平滑后的变盘指数：

$$
B_t = \mathrm{MA}_m(I_t)
$$

变盘指数的一阶差分为：

$$
\Delta B_t=B_t-B_{t-1}
$$

MVP基准参数暂定为：

- 排名比较及滚动标准差窗口：`M = 220` 个交易日；
- 平滑窗口：`m = 20` 个交易日；
- 动量窗口：240个交易日；
- 反转窗口：60个交易日。

### 3.2 动量与反转切换

- 当 $\Delta B_t<0$ 时，行业排名扰动收敛，使用动量信号；
- 当 $\Delta B_t>0$ 时，行业排名扰动扩大，使用反转信号；
- 当 $\Delta B_t=0$ 时，暂定沿用上一期信号，最终规则仍需确认。

动量因子使用过去240个交易日累计收益率，收益率越高得分越高。反转因子使用过去60个交易日累计收益率的相反数，过去收益率越低，反转得分越高。

### 3.3 行业分组与组合构建

1. 每月根据 $\Delta B_t$ 选择动量因子或反转因子；
2. 使用被选中的因子对当期全部有效行业进行横截面排序；
3. 将有效行业划分为5组；
4. 选择因子得分最高的第5组，即排名前20%左右的行业；
5. 将入选行业映射到可交易ETF；
6. 组内采用等权配置；
7. 持有至下一调仓期后重新计算信号和目标组合。

## 4. 信号与交易时间顺序

基准时间顺序应为：

1. 在月末调仓信号日 $t$ 收盘后，使用截至当日已经获得的数据计算变盘指数、状态和行业排序；
2. 在下一交易日 $t+1$ 执行调仓；
3. 组合收益从 $t+1$ 调仓执行后开始计算；
4. 代码中的目标权重必须向后移动至可交易时点，避免未来函数和前视偏差。

## 5. 程序安装与快速运行

以下命令将在回测程序、配置文件和依赖清单上传到仓库后可用。代码尚未上传时，执行命令会因缺少文件而失败。

### 5.1 克隆仓库并安装依赖

```powershell
git clone https://github.com/lugayoung666-boop/industry-etf-rotation.git
cd industry-etf-rotation
pip install -r requirements.txt
python run_backtest.py --demo
```

`--demo` 使用程序提供的演示数据离线跑通流程，主要用于检查环境、配置和回测链路，不代表真实策略表现。

### 5.2 第一次下载AkShare数据

```powershell
python run_backtest.py --download --output output_akshare
```

首次下载后，行情缓存保存在 `data/cache/`；ETF或行业映射配置位于 `config/universe.yaml`；策略参数位于 `config/strategy.yaml`。

### 5.3 后续只读取本地数据

```powershell
python run_backtest.py --source local --output output_local
```

`--source local` 为默认模式，不调用网络接口。如果本地文件不存在或日期覆盖不足，程序应提示用户先执行 `--download`，不得在未提示的情况下自动改变样本区间。

### 5.4 使用Tushare数据源

使用Tushare前需要相应接口权限，并通过环境变量提供Token。Token不得写入代码、配置文件或提交到Git仓库。

```powershell
$env:TUSHARE_TOKEN="你的token"
python run_backtest.py --source tushare --output output_tushare
```

AkShare和Tushare均可用于获取真实行情数据；两者只是数据来源不同。不同数据源的复权口径、日期覆盖和缺失值情况需要分别检查。

## 9. 数据需求

信号层初步需要：

- 行业代码和行业名称；
- 行业分类口径；
- 交易日期；
- 行业指数后复权收盘价；
- 行业滚动月度收益率。

ETF交易层初步需要：

- ETF代码和名称；
- 所属行业或主题；
- 跟踪指数；
- 上市日期；
- 交易日期；
- 复权开盘价和复权收盘价；
- 涨跌幅；
- 成交额。

ETF上市前不可交易；上市时间不足、无法形成有效信号或无法完成行业映射的ETF，不纳入当期可交易标的。

## 10. 回测假设

- 第一阶段采用月频调仓；
- 信号层优先基于行业指数，交易层通过行业到ETF映射完成；
- 月末信号在下一交易日执行；
- 多头组合持有第5组，组内等权；
- 交易成本和滑点设计为可配置参数；
- 第一版现金收益率和无风险利率暂定为0；
- 缺失、停牌及异常价格必须经过明确的数据清洗和审计；
- ETF映射和流动性筛选可能产生样本选择及幸存者偏差；
- 第一版暂不考虑申赎限制、冲击成本和资金容量约束。
