# 基于反转效应的行业主题ETF轮动策略

## 1. 项目简介

本项目是一个基金/ETF轮动策略的小型金工实习项目，目标是围绕行业或主题ETF构建、回测并评估一个基于反转效应的轮动策略。

项目当前处于方案设计与流程搭建阶段，README用于明确研究范围、最小可运行策略、数据需求、回测流程和后续开发计划。现阶段不展示任何实证结果，也不假设策略已经取得收益。

## 2. 研究对象与策略思想

第一阶段以行业或主题ETF为主要交易标的，研究对象按照行业或主题划分，包括但不限于医药、消费、科技、红利、军工和新能源。场外基金作为后续扩展方向，第一版不混用ETF价格回测与场外基金净值回测。

本项目不开展个股层面的选股研究。第一版策略关注反转效应：在每个调仓信号日，根据各ETF过去一段时间的累计收益率进行排序，优先选择近期表现相对较弱的ETF，构建下一期组合。该策略不是动量策略，第一版买入的是近期相对弱势、可能出现反转的ETF。

## 3. 最小可运行策略

最小可运行策略（MVP）用于先跑通完整回测流程，保证数据读取、信号生成、组合构建、调仓交易和业绩统计能够形成闭环。

已经确定的策略要求：

1. 建立行业或主题ETF候选池；
2. 在每个调仓信号日，计算各ETF过去一段时间的累计收益率；
3. 按累计收益率从低到高排序；
4. 选择近期表现较弱的若干只ETF，形成反转信号；
5. 第一版采用等权配置，保证策略逻辑简单、结果容易解释；
6. 持有至下一个调仓期，再重新计算信号并调整组合；
7. 回测中考虑交易成本、换手率和ETF上市时间；
8. 信号必须使用调仓信号日收盘后能够获得的数据，避免未来函数和前视偏差。

反转信号定义如下。对ETF \(i\)，在调仓信号日 \(t\) 计算过去 \(L\) 个交易日的累计收益率：

$$
R_{i,t}(L) = \frac{P_{i,t}}{P_{i,t-L}} - 1
$$

其中：

- \(i\)：ETF标的；
- \(t\)：调仓信号日；
- \(L\)：回看窗口长度；
- \(P\)：复权收盘价；
- \(R\)：过去 \(L\) 个交易日的累计收益率；
- \(N\)：每期入选ETF数量。

累计收益率越低，反转排序越靠前。第一版选取累计收益率最低的 \(N\) 只ETF。

信号与交易的时间顺序：

- 在调仓信号日 \(t\) 收盘后，使用能够获得的数据计算信号；
- 在下一个交易日 \(t+1\) 以开盘价执行调仓；
- 下一期组合收益必须使用调仓执行后的价格变化计算；
- 代码中需要将信号和持仓权重向后移动，避免使用当日尚未获得的信息。

暂定的回测参数：

- 候选池：第一版暂选6只分别代表医药、消费、科技、红利、军工和新能源的ETF；
- 回看窗口：20个交易日；
- 调仓频率：月度调仓；
- 入选数量：选取过去20个交易日累计收益率最低的2只ETF；
- 权重方式：两只ETF等权配置，每只50%；
- 交易成本：暂按单边0.1%的综合成本计算，并设计为可修改参数；
- 基准：6只候选ETF的等权组合。

以上MVP默认值仅用于 `run_pipeline.py` 直接跑通流程和验证回测链路，不代表最优参数。具体参数将在数据确定、流程验证和mentor确认后进一步调整。

## 4. 回测流程

阶段1计划先建立单脚本 `run_pipeline.py`，按以下顺序跑通完整流程：

```text
数据读取与清洗 -> 收益率计算 -> 反转信号生成 -> ETF排序与筛选 -> 组合赋权 -> 调仓交易模拟 -> 净值计算 -> 业绩指标输出
```

阶段1的重点不是追求复杂模型，而是验证策略研究和回测框架是否能够完整运行，并检查是否存在未来函数、交易日错位、缺失值处理不当等基础问题。

## 5. 模块划分

阶段2将在单脚本流程跑通后，将代码拆分为结构清晰、便于维护和复用的回测模块：

1. 数据处理模块：读取并清洗ETF行情、统一交易日期、处理缺失值；
2. 指标与信号模块：计算历史收益率、生成反转信号并完成ETF排序；
3. 赋权与组合构建模块：筛选目标ETF并生成目标持仓权重；
4. 组合交易与调仓模块：根据调仓频率更新持仓，计算换手率和交易成本；
5. 业绩统计模块：计算净值及风险收益指标；
6. 主程序模块：按照统一顺序调用以上模块，完成完整回测。

## 6. 数据需求

初步所需字段包括：

- ETF代码
- ETF名称
- 所属行业或主题
- 跟踪指数
- 上市日期
- 交易日期
- 复权开盘价
- 复权收盘价
- 涨跌幅
- 成交额

使用复权价格是为了使收益率能够反映分红等价格调整。反转信号使用复权收盘价计算，交易执行价格使用下一交易日复权开盘价。第一版优先选择每个行业或主题中一只代表性、流动性较好的ETF，避免重复跟踪相同指数。后续可以扩展至场外基金或更完整的基金池。

如果最终使用基金净值，需要单独建立相应数据接口，不能直接与ETF价格字段混用。数据来源、数据频率、复权方式和候选池名单需要后续进一步确认。

## 7. 回测假设

初步回测假设如下：

- 交易标的为行业或主题ETF；
- 每个调仓信号日 \(t\) 收盘后根据已知历史数据生成信号，并在下一个交易日 \(t+1\) 以开盘价执行调仓；
- 调仓后持有至下一调仓期；
- 第一版组合采用等权配置；
- 回测考虑交易成本和换手率；
- ETF上市前不可交易，候选池构建需要记录ETF上市日期，避免在ETF上市前使用该标的；
- 上市时间不足以计算信号的ETF暂不纳入当期有效候选池；
- 如果某期有效ETF数量不足 \(N\) 只，则每个有效入选标的仍按 \(1/N\) 配置，缺少的名额对应权重保留为现金，不对剩余ETF重新归一化；
- 第一版暂假设现金收益率为0；
- 第一版计算夏普比率时暂定无风险利率为0，后续可替换为指定的无风险利率序列；
- 缺失价格、停牌或异常交易数据需要在数据清洗阶段统一处理；
- 当前流动性筛选可能带来样本选择或幸存者偏差，后续稳健性分析中需要讨论；
- 暂不考虑申赎限制、冲击成本和资金容量约束。

以上假设用于第一版流程验证，后续可根据数据质量和mentor反馈进一步细化。

## 10. 开发计划

阶段1：单脚本跑通流程。

- 明确ETF候选池和样本区间；
- 准备并清洗基础行情数据；
- 编写 `run_pipeline.py`；
- 实现收益率计算、反转信号、排序筛选和等权组合；
- 加入调仓交易模拟、交易成本和换手率计算；
- 输出净值曲线、绩效指标和每期持仓记录；
- 检查信号生成时间，避免未来函数和前视偏差。

阶段2：模块化回测。

- 将单脚本拆分为数据、信号、组合、交易、绩效和主程序模块；
- 统一参数配置方式；
- 增加必要的数据检查和结果校验；
- 比较不同回看窗口、入选数量、调仓频率和交易成本设定；
- 完善图表、表格和项目说明。
