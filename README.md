# 基于“变盘指数”的行业主题ETF动量-反转轮动策略

## 1. 项目简介

本项目是一个基金/ETF轮动策略的小型金工实习项目，第一阶段按照“轮动回测”策略构建最小可运行版本（MVP）。
核心思路：先构造“变盘指数”，判断当前行业结构更适合采用动量信号还是反转信号，再对行业进行横截面排序和轮动配置，最终将入选行业映射到对应基金/ETF。

项目当前处于方案设计与流程搭建阶段，本文件用于明确研究范围、MVP策略逻辑、数据需求、回测流程和后续开发计划。由于缺乏数据支撑，现阶段不展示任何实证结果，也不假设策略已经取得收益。

## 2. 研究对象与策略思想

第一阶段以行业或主题ETF为主要交易标的，行业或主题示例包括但不限于医药、消费、科技、红利、军工和新能源。这些仅作为行业或主题方向示例，不代表候选池固定为6只ETF。MVP应尽可能使用覆盖较完整的行业池，以支持横截面排名和五组分层。

研报原始回测使用中信一级行业指数后复权收盘价。当前项目计划在此基础上进行ETF化：

- 信号层：优先使用覆盖时间较长、分类稳定的行业指数计算变盘指数和行业因子；
- 交易层：将入选行业映射到对应的代表性行业或主题ETF；
- 如果暂时无法取得完整行业指数数据，可以先使用覆盖时间足够长的ETF池验证程序流程，但这属于简化MVP；
- ETF映射需要考虑跟踪指数、上市日期、流动性和重复暴露。

本项目不开展个股层面的选股研究，场外基金作为后续扩展方向，第一版不混用ETF价格回测与场外基金净值回测。

## 3. MVP

MVP用于先跑通完整回测流程，保证数据读取、行业收益率计算、变盘指数构造、状态判断、行业分组、ETF映射、组合构建、调仓交易和业绩统计能够形成闭环。

已经确定的策略要求：

1. 建立覆盖较完整的行业指数池，并准备对应ETF映射关系；
2. 在每个调仓期构造变盘指数，判断当前采用动量信号还是反转信号；
3. 使用被选中的信号对全部行业进行横截面排序；
4. 将行业分为5组，选择因子得分最高的第5组作为多头组合；
5. 将入选行业映射到对应ETF，并在组内等权配置；
6. 持有至下一调仓期，再重新计算变盘指数、选择因子并调整组合；
7. 回测中考虑换手率、ETF上市时间和行业到ETF映射约束；
8. 在调仓日 \(t\) 收盘后计算信号，持仓权重从下一交易日 \(t+1\) 开始生效，避免未来函数和前视偏差。

### 变盘指数构造

设行业数量为 \(N\)。在每个交易日 \(t\)，暂用过去20个交易日的累计收益率近似滚动1个月收益率：

$$
r_{i,t}^{1M} = \frac{P_{i,t}}{P_{i,t-20}} - 1
$$

其中 \(P\) 为行业指数后复权收盘价。每天根据该滚动1个月收益率对所有行业进行横截面排名，再比较行业 \(i\) 在 \(t\) 时点与 \(M\) 个交易日前的排名变化。20日只是MVP暂定口径，应设计为可配置参数。

将排名变化除以行业数量 \(N\) 并取绝对值，得到标准化排名变化：

$$
Rank\_std_{i,t} = \left|\frac{\Delta Rank_{i,t}}{N}\right|
$$

对全部行业的标准化排名变化取横截面均值：

$$
R_t = \frac{1}{N} \sum_{i=1}^{N} Rank\_std_{i,t}
$$

对 \(R_t\) 计算过去 \(M\) 个交易日的滚动标准差：

$$
I_t = std_M(R_t)
$$

对 \(I_t\) 进行 \(m\) 日移动平均，得到平滑后的变盘指数：

$$
B_t = MA_m(I_t)
$$

计算变盘指数的一阶差分：

$$
\Delta B_t = B_t - B_{t-1}
$$

其中：

- \(N\)：行业数量；
- \(M\)：排名变化比较窗口和滚动标准差窗口，MVP暂定为220个交易日；
- \(m\)：变盘指数平滑窗口，MVP暂定为20个交易日；
- \(Rank\_std_{i,t}\)：行业 \(i\) 在 \(t\) 时点的标准化排名变化；
- \(R_t\)：全部行业标准化排名变化的横截面均值；
- \(I_t\)：\(R_t\) 在过去 \(M\) 个交易日内的滚动标准差；
- \(B_t\)：经过 \(m\) 日移动平均平滑后的变盘指数；
- \(\Delta B_t\)：变盘指数的一阶差分，用于判断动量或反转状态。

MVP暂定 \(M=220\) 个交易日，平滑窗口 \(m=20\) 个交易日。上述参数来自研报基准设定，后续再进行参数敏感性检验。

### 动量与反转择时规则

- 当 \(\Delta B_t < 0\) 时，说明行业排名扰动正在收敛，市场主线相对稳定，使用动量信号；
- 当 \(\Delta B_t > 0\) 时，说明行业排名扰动正在扩大，原有强弱结构可能被重新定价，使用反转信号；
- 当 \(\Delta B_t = 0\) 时，处理方式暂列为待确认事项，可以沿用上一期信号。

MVP暂定：

- 动量因子：过去240个交易日累计收益率，收益率越高得分越高；
- 反转因子：过去60个交易日累计收益率的相反数，过去收益率越低，反转得分越高。

### 行业组合构建规则

1. 每月根据 \(\Delta B_t\) 选择动量因子或反转因子；
2. 使用被选中的因子对全部行业进行横截面排序；
3. 将行业分为5组；
4. 选择因子得分最高的第5组作为多头组合，即行业池排名前20%左右的行业；
5. 组内采用等权配置；
6. 下一调仓期重新计算变盘指数、选择因子并更新组合；
7. 在调仓日 \(t\) 收盘后计算信号，持仓权重从下一交易日 \(t+1\) 开始生效；程序中权重至少滞后一交易日，不能用 \(t\) 日信号解释 \(t\) 日收益。

### MVP回测设定

- 调仓频率：第一阶段先做月频MVP；
- 变盘指数回望期：220日；
- 平滑窗口：20日；
- 动量窗口：240日；
- 反转窗口：60日；
- 行业分组：5组；
- 多头组合：持有第5组；
- 权重方式：组内等权；
- 交易成本：指数层方法复现时暂设为0，以便与研报方法口径比较；ETF化应用回测时加入可配置的佣金、滑点等综合交易成本；
- 基准：暂定为行业等权组合；
- 周频策略：作为后续扩展，不纳入第一阶段MVP。

以上MVP默认值用于 `run_pipeline.py` 直接跑通流程和验证回测链路，不代表最优参数。具体参数将在数据确定、流程验证和mentor确认后进一步调整。

## 4. 回测流程

阶段1计划先建立单脚本 `run_pipeline.py`，按以下顺序跑通完整流程：

```text
数据读取与清洗
-> 行业收益率计算
-> 行业横截面排名
-> 变盘指数构造
-> 变盘指数一阶差分
-> 动量/反转状态选择
-> 行业因子排序与五组分层
-> 选择第5组
-> 行业到ETF映射
-> 组合等权赋权
-> 月度调仓
-> 交易成本与净值计算
-> 业绩统计
```

阶段1主要验证研报核心策略逻辑和ETF化回测框架是否能够完整运行，并检查是否存在未来函数、交易日错位、行业映射不一致、缺失值处理不当等基础问题。

## 5. 模块划分

阶段2将在单脚本流程跑通后，将代码拆分为结构清晰、便于维护和复用的回测模块：

1. `data`：指数和ETF数据读取、清洗及映射；
2. `regime`：变盘指数构造及状态判断；
3. `signals`：动量因子、反转因子和因子切换；
4. `portfolio`：行业分组、ETF筛选和组合赋权；
5. `backtest`：持仓、调仓、交易成本和净值计算；
6. `performance`：收益、波动率、夏普比率、最大回撤、RankIC等统计；
7. `run_pipeline`：串联完整MVP流程。

## 6. 数据需求

初步所需字段包括：

- 行业代码或行业名称
- 行业分类口径
- 行业指数交易日期
- 行业指数后复权收盘价
- 行业指数滚动1个月收益率
- ETF代码
- ETF名称
- ETF所属行业或主题
- ETF跟踪指数
- ETF上市日期
- ETF交易日期
- ETF复权开盘价
- ETF复权收盘价
- ETF涨跌幅
- ETF成交额

使用复权价格是为了使收益率能够反映分红等价格调整。信号层优先使用行业指数后复权收盘价计算变盘指数、动量因子和反转因子；交易层使用ETF复权价格计算调仓执行和组合净值。

如果最终使用基金净值，需要单独建立相应数据接口，不能直接与ETF价格字段混用。数据来源、行业分类口径、复权方式、行业指数与ETF映射关系需要后续进一步确认。

## 7. 回测假设

初步回测假设如下：

- 第一阶段先做月频MVP；
- 信号层优先基于行业指数计算，交易层通过行业到ETF映射完成ETF化回测；
- 如果暂时无法取得完整行业指数数据，可以先使用覆盖时间足够长的ETF池验证程序流程，但需要在结果解释中说明这是简化MVP；
- 每个调仓日 \(t\) 收盘后根据已知历史数据生成信号，并在下一个交易日 \(t+1\) 以开盘价执行调仓；
- 程序中持仓权重至少滞后一交易日，不能用 \(t\) 日信号解释 \(t\) 日收益；
- 调仓后持有至下一调仓期；
- 多头组合持有因子得分最高的第5组，组内等权；
- 回测考虑换手率；指数层方法复现时交易成本暂设为0，ETF化应用回测时加入可配置的佣金、滑点等综合交易成本；
- ETF上市前不可交易，ETF映射需要记录上市日期，避免在ETF上市前使用该标的；
- 上市时间不足或无法完成有效映射的ETF暂不纳入当期可交易标的；
- 第一版暂假设现金收益率为0；
- 第一版计算夏普比率时暂定无风险利率为0，后续可替换为指定的无风险利率序列；
- 缺失价格、停牌或异常交易数据需要在数据清洗阶段统一处理；
- 当前ETF映射和流动性筛选可能带来样本选择或幸存者偏差，后续稳健性分析中需要讨论；
- 暂不考虑申赎限制、冲击成本和资金容量约束；
- 周频策略作为后续扩展，不纳入第一阶段MVP。

以上假设用于第一版流程验证，后续可根据数据质量和反馈后进一步细化。

## 8. 业绩评价指标

计划至少输出以下回测结果和评价指标：

- 策略净值曲线
- 累计收益率
- 年化收益率
- 年化波动率
- 夏普比率
- 最大回撤
- 换手率
- 交易成本
- RankIC
- 每期行业状态、因子选择、行业分组及持仓记录
- 与基准组合的对比结果

RankIC定义为：每个调仓期计算当期因子横截面排名与下一持有期行业收益率排名之间的相关系数，用于检验因子是否具有行业排序能力。RankIC必须使用下一期收益率，不能使用当期收益率。

基准暂定为行业等权组合，最终基准有待进一步确认。

## 10. 开发计划

阶段1：按照研报核心策略，用 `run_pipeline.py` 跑通完整MVP流程。

- 明确行业分类口径、行业指数池和样本区间；
- 准备行业指数行情、ETF行情和行业到ETF映射表；
- 编写 `run_pipeline.py`；
- 实现行业收益率计算、行业横截面排名和变盘指数构造；
- 实现 \(\Delta B_t\) 对动量/反转状态的选择；
- 实现动量因子、反转因子、五组分层和第5组选择；
- 实现行业到ETF映射、等权赋权、月度调仓、交易成本和净值计算；
- 输出净值曲线、绩效指标、状态判断、行业分组和每期持仓记录；
- 检查信号生成时间，避免未来函数和前视偏差。

阶段2：拆分模块，建立可维护的ETF化回测框架。

- 将单脚本拆分为 `data`、`regime`、`signals`、`portfolio`、`backtest`、`performance` 和 `run_pipeline`；
- 统一参数配置方式；
- 增加必要的数据检查、行业映射检查和结果校验；
- 比较不同变盘指数窗口、动量窗口、反转窗口、交易成本和调仓频率设定；
- 完善图表、表格和项目说明。

阶段3：策略扩展与稳健性检验。

- 对变盘指数窗口、平滑窗口、动量窗口和反转窗口进行敏感性检验；
- 比较指数层结果与ETF化回测结果；
- 评估是否进一步完成周频版本；
- 完善变盘指数触发规则，并研究仓位控制、多周期共振及周频辅助监测。
